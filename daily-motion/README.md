# Daily Remotion scenes — limited rollout

The new pipeline is separate from the disabled legacy shape/JSON generator. It uses
Haiku to design a brief scene, write React/Remotion source, and check factual grounding.
One code repair/recheck is allowed. This is not a guarantee of creative quality.

## Scope and controls

- Default categories: `World News,Business` only.
- Daily public Morning/Evening/Daily records whose digest grounding completed; no
  private/shared-user rows, weekly/monthly jobs or history backfill.
- Trigger: non-blocking `saveBriefingSources` hook after publication. Startup resumes
  only today's already queued tasks; a background minute tick retries interrupted work.
- Existing attributed short script is reused exactly. If it is missing, the planning
  call derives a concise visual script from the full checked source; factual audit
  checks the derived script too. This does not rewrite or publish the news/audio.
- One cached code asset serves exact Full and unambiguous single-story Quick aliases.
  A multi-story recap sentence is not attached to a guessed single-story scene.
- All input text corrections affect content signatures. Ready assets are reused.

Environment settings (central defaults in source.js):

```
DAILY_MOTION_ENABLED=true
DAILY_MOTION_CATEGORIES=World News,Business
DAILY_MOTION_MODEL=claude-haiku-4-5-20251001
DAILY_MOTION_DAILY_USD=3
DAILY_MOTION_MAX_DAILY_JOBS=24
DAILY_MOTION_PUBLIC_ORIGIN=https://the-ai-rundown-backend.onrender.com
```

$0.125 is reserved per new story, so up to24 new/changed scenes can reserve at most$3
per UAE calendar day across categories/languages/slots. Actual provider usage is
recorded separately, including failed calls/repairs. Reservations are conservative;
unused amounts are not billed but their slots stay reserved until the next day.
A per-call worst-case token bound prevents the job exceeding its reserved ceiling.
Increasing categories does not increase the budget automatically. Raising the model
or volume requires reviewing these ceilings. Credit/auth failures stop the worker.

## Delivery and isolation

No model call is made by consumer lookup. Saved JSX is checked, then esbuild compiles
only react/remotion imports against one common pinned runtime. The cached runtime is
shared across story frames; each compiled story is a small separate program.

Generated code never enters the app's React context. The parent mounts a single current
visible iframe with `sandbox="allow-scripts"` and no same-origin permission. CSP permits
only the exact runtime URL and hash of the saved inline script, with no network, images,
media, fonts, nested frames or forms. The generated scene cannot own audio or timers.
Remotion Player remains paused; the app sends normalized narration position using
postMessage. Ready/error messages are checked against the actual iframe window/id.
Read, Settings Off, background and offscreen views unload the frame. Runtime errors or
load timeouts fall back to text/audio. Static checks and isolation reduce risk; they
are not a formal proof of code safety or performance on every phone.

Storage uses a private `daily-remotion-scenes` bucket, created with the service role.
Atomic non-overwriting queue/claim/budget files prevent duplicate charges across
instances/restarts. Interrupted claims recover once after20minutes; normal failures
are not re-generated by viewers. Historical claims/reservations are preserved.
No SQL migration is needed. Runtime/frame endpoints expose only compiled public-news
artwork, never source credentials or provider access. Status is read-only:
`GET /api/daily-motion/status`.

A one-time rollout check queues at most one saved World story and one saved Business
story, under the same daily caps. Remove its startup call after live verification.

Tests: source eligibility/provenance, exact aliases, no on-demand spending, bounded
budget/restarts, duplicate workers, recovery, grounding/credit failures, compilation
and CSP. Frontend tests cover lifecycle, parent/iframe message verification, Read/Off,
source access and excluded categories/period recaps. Browser QA uses a prior approved
Haiku scene as a technical fixture, never presented as a new World/Business story.
